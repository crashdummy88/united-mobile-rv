Troubleshoot

Peplink: WAN flapping / failover not sticking

When the coach Wi-Fi stays up but apps drop every few minutes, or failover “works in the driveway” and dies on the road, separate radio/sky problems from router policy, power, and SpeedFusion configuration. United Mobile RV is a Peplink Certified Associate. Firmware only from peplink.com.

Always name the mode you configured: local outbound failover ≠ SpeedFusion Hot Failover ≠ Bonding ≠ Smoothing.

Decision tree (do in order)

1) Power (most RV “mystery flaps”)

  • Measure voltage under load (A/C start, inverter surge). Brown-outs reset modems and flap health checks.
  • Router + cellular modem must ride the same chassis fused DC. Do not park modem/antenna amp on a cigarette-lighter or shared noisy tap while the chassis feed looks “clean.”
  • Starlink PoE injector on its own fused path — brownout-aware; do not share with router/modem DC.
  • Fuse labeled; conductors sized for path length. Exact amps: measure-on-site (no invented single number).

2) RF / sky (before touching Peplink policy)

  • Outdoor cell usable on that carrier? Peplink cannot invent RF — see weBoost guide only for weak-but-present signal.
  • Starlink clear sky? Trees/eaves win — Starlink RV guide.
  • Antenna isolation: cellular, Starlink routing, and weBoost outdoor antennas crowded on one roof corner create “firmware” tickets that are RF.

3) SIM / modem auth

  • Router-legal plan (many phone plans block/throttle routers).
  • Both modems registered; APN correct; trays labeled and seated after vibration.
  • Dual-SIM ≠ double speed — insurance + map fill.

4) Mode truth (name it)

Open the config and write down exactly what is running:

  • Local outbound priority / weighted balance — no SpeedFusion tunnel; sessions may drop on handoff.
  • SpeedFusion Hot Failover — needs peer (Peplink / FusionHub / SpeedFusion Connect) + healthy secondary.
  • Bonding — peer required; Starlink+cell can hurt interactive apps even when Mbps look good. Never expect automatic 2×.
  • Smoothing — redundant copies; burns more metered data.

Entry chassis (BR1 Mini, some BR2/Micro, B One class) may need PrimeCare / feature pack before SpeedFusion modes unlock — verify invoice/SKU.

5) WAN Health Checks

  • One brittle health-check IP = false flaps when that target blocks ICMP/HTTP.
  • Diversify checks; fix power/RF root cause instead of forever tightening thresholds.
  • After any power or roof work, re-test intentional WAN kills in the driveway.

6) Starlink Ethernet handoff

  • Official Starlink Ethernet adapter or Starlink router LAN → Peplink WAN.
  • Confirm link lights and that Peplink sees the WAN before blaming SpeedFusion.
  • PoE path brownout = dish drops = Peplink flaps.

7) Firmware source

  • peplink.com / InControl 2 only (`https://incontrol2.peplink.com/`). No random mirrors.

---

Owner self-checks (15 minutes)

  1. Photo: WAN wiring, SIM carriers, fuse block, PoE injector feed.
  2. Toggle each WAN off once; watch whether apps drop or stick.
  3. Note whether interactive apps suffer more than bulk downloads (bonding mismatch clue).
  4. Write the configured mode name on a sticker inside the cabinet.
